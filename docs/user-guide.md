# 使用指南

按界面区域说明每个页面能做什么。名词解释见 [核心概念](concepts.md)。

## 界面布局

- **左侧栏：** 顶部是「公司」，下面是项目列表（项目多时有搜索框）；底部是「模型」「用量」「设置」。侧栏可以收成窄条。
- **右上角：** 小铃铛，汇总需要你处理的事（审批、议题、卡住提示等）。
- **项目页：** 顶部一排标签页：职责、导入、群聊、计划、任务、议题、会议、行动项、成员、记忆、文档。

## 公司页

- **员工：** 新建、编辑、改名、归档员工；选择 LLM 通道和模型；设置能力上限（自动或 1–5）；编辑身份说明。
- **项目：** 「＋ 新建 / 导入项目」。已有代码的目录会走导入流程；全新项目不要勾「已有项目」。
- **公司记忆与简介：** 公司级的约定，所有项目共享。

## 项目页各标签

| 标签 | 用途 |
|---|---|
| 职责 | 开始 / 暂停 / 停止**自主推进**，设置每批次预算和自动续批次；看当前批次状态 |
| 导入 | 已有项目的只读扫描、测试基线，确认后进入团队维护阶段 |
| 群聊 | 项目的主时间线：你发消息（`@员工` 可以直接派活）、员工汇报、审批请求；支持 Markdown |
| 计划 | 项目目标与硬性约束；计划条目（依赖、等级、指派、等待原因）；目标变更提议 |
| 任务 | 每个任务的分支、改动文件、diff、合并预检；合并、放弃 |
| 议题 | 需要决定的事；有 AI 负责人时由它裁决，升级给你时在这里处理 |
| 会议 | 对齐会、评审会的发言和纪要；你也可以参与发言 |
| 行动项 | 会议和评审产生的待办，负责人会整理 |
| 成员 | 项目成员和角色；添加成员；**交接…**（把角色交给别人） |
| 记忆 | 项目记忆：查看、编辑、确认 |
| 文档 | 主分支 `docs/` 下的 Markdown，只读 |

## 常见操作

### 新建一个项目并让团队开工

见 [快速开始](getting-started.md)。要点：目标里写清技术栈、不做什么、验收标准。

### 给员工派一个临时任务

在「群聊」里 `@员工名 要做的事`。员工在自己的 worktree 里做，做完后在「任务」页评审、合并。

### 审批

员工要做越界的事（写工作区之外、危险命令）时，会弹审批：允许、拒绝，或「允许并加入白名单」（网络域名）。沙箱内的普通命令自动放行。

### 改项目目标

你可以直接在「计划」页改。AI 想改目标时只能提议，你在这里批准或驳回（可以修改后批准）。

### 处理批次的「等你处理」

先看提示里的原因，再看「计划」「议题」「行动项」「任务」。处理后点「再开一个批次」。

### 换负责人 / 角色交接

「成员」页 →「交接…」：选要交接的角色和接手的员工，原员工先写摘要，再执行交接。原员工进行中的任务会自动放弃（改动保留）；他名下还没开始的活可选：不动、交给新人、改回「未指定」。新负责人在下一个批次开头会做一次接手复盘：补等级、按能力重新分配。

### 看用量

左下角「用量」：按员工、模型、用途汇总调用次数、耗时、费用；也能看到每个会话的上下文占用。

### 全局设置

左下角「设置」：沙箱网络白名单、会话上下文上限、是否阻止 Mac 在批次运行时休眠等。

## 命令行

`crewforge` 命令行用来验证核心链路和排错：

```sh
cargo run -p crewforge-cli -- employee list
cargo run -p crewforge-cli -- events 50
cargo run -p crewforge-cli -- tasks <项目目录>
cargo run -p crewforge-cli -- cost 7
```

完整子命令见 `crates/cli/src/main.rs` 开头的注释。数据目录用环境变量 `CREWFORGE_HOME` 指定。
