# 连接本地模型（自建端点）

员工可以连你自己搭的 **Anthropic 兼容服务**（例如另一台电脑上的 Ollama），而不用本机的 Claude 订阅。这样的员工不占订阅额度，费用记 0。

## 工作方式

Crewforge 只对**该员工的 CLI 进程**注入 `ANTHROPIC_BASE_URL` 等环境变量，三个模型档位别名都指向端点上的模型；不碰你本机的 Claude 登录，也不受你切换账号影响。启动参数里带 `--setting-sources ""`，用户级 `settings.json` 影响不到。令牌（如果有）存在系统钥匙串里。

## 配置步骤

1. **在服务器上：** 以 Ollama 为例，让它监听局域网：设置环境变量 `OLLAMA_HOST=0.0.0.0` 并放行端口（默认 11434），拉取模型（`ollama pull <模型>`，`ollama list` 能看到实际标签）。
   > Ollama 本身没有认证，**只在局域网或 Tailscale 这类私有网络里用**，不要暴露到公网。
2. **在 Crewforge 里：** 打开左下角「模型 → 自建端点」，新建端点：
   - 地址：以 `http://` 或 `https://` 开头，例如 `http://192.168.1.20:11434`。
   - 模型：填端点上的实际模型标签，每行一个。
   - 上下文窗口：填模型实际加载的上下文长度。员工的会话会在窗口的约七成时换新会话。
   - 令牌：有就填，没有留空。
3. 点「测试连接」，通过后到「公司」页新建员工，把 **LLM 通道**选成这个端点并选模型。
4. 能力上限默认给 2 级。本地模型适合机械改动、补测试这类低等级的活，难的活交给更强的员工。

## 并发

端点的「并发」是同时最多几个员工在用它。本地模型通常**只能真正串行处理**，建议设为 **1**：设得比实际能力高，多出来的请求会在服务器上排队，排得太久没有任何输出就会被看门狗终止（默认连续 45 分钟没有输出）。Crewforge 自己也有排队：名额空出来时按优先级放行（任务和人发起的优先，其次是裁决和评审，再其次是会议和计划，最后是纪要、整理和文档），等了很久的低优先级也会逐步提升。

员工等你批准某个操作时会先把名额让出去，批准后重新排队，不会堵住别人。

## 预算开关

端点上有「限制批次预算」开关，默认开：这个端点上的调用计入自主推进批次的预算。关掉后只统计、不限制，适合自己的机器、不花钱的本地模型。

## macOS 的本地网络授权

访问局域网里的服务需要 macOS 的「本地网络」权限，授权绑定应用签名。**每次重装都可能失效**，重装后到「模型 → 自建端点」点一次「测试连接」。务必用 `scripts/install-mac.sh` 重装（它会重新做完整签名）。从 IDE 内置终端启动的进程没有这个权限，直接访问内网地址会报 `EHOSTUNREACH`，而 `curl` 不受限，容易误判。

## 常见问题

- **「CLI 在返回结果前退出」：** 先点「测试连接」；再检查模型标签是否写对、服务器是否可达。
- **很慢、长时间没输出：** 本地模型处理长上下文本来就慢。看卡住提示里「端点上同时有几个员工在用」；降低并发，缩小上下文窗口，或把大任务拆小。
- **模型回答不遵守格式：** 负责人的 JSON 回复格式不对会带着原因重试，最多 3 次；本地模型当负责人容易失败，建议负责人用更强的模型。
