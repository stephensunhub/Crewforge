# 常见问题与排错

排错的总原则：**先看事件**。「员工卡片 → 工作日志」、「人工介入」页和项目「计划」页的等待原因，都是从事件流汇总出来的。

## 员工看起来没动静

- **在等你：** 去「人工介入」页和右上角的通知（小铃铛）看有没有待批准的命令、待决定的事。员工等审批时会占着时间，但不会占端点名额。
- **在排队：** 自建端点上，同一时间只有「并发」个员工在跑，其余在等名额，界面会显示「在等模型名额」。
- **模型慢：** 本地模型处理长上下文可能要几分钟甚至更久，卡住提示会写出「最近一次动作在几分钟前」。
- **被看门狗终止：** 连续很久没有任何输出会终止这一轮（默认 45 分钟），工作区里已有的改动保留。

## 批次状态是「等你处理」

提示里会写原因。常见的有：没有可开始的条目（前置失败或被阻塞）、负责人认为需要你来定、合并被拦。到「计划」页看哪些条目失败或阻塞，到「议题」「行动项」看有没有待决定的事。

## 合并被拦

- 主工作区有未提交的改动：在项目目录里手动改了文件。请还原或提交，**保持主工作区干净**。
- 评审里还有未处理的「合并前」行动项：处理它们，或明知如此仍然合并。

## 重装后所有调用都失败

多半是 macOS「本地网络」授权失效，见 [连接本地模型](endpoints.md)。点一次「测试连接」。

## 数据库版本

装好的应用**拒绝打开比自己新的数据库**，也不能回退。改了数据库结构后要用 `scripts/install-mac.sh` 重装。想看数据库内容时，先复制 `crewforge.db`（连同 `-wal`、`-shm`）再用 `sqlite3 -readonly` 打开，不要直接对在用的库写。

## 员工进程残留

所有员工进程都登记在 `children.pids` 里，应用退出时统一终止，下次启动会清理孤儿进程。手动检查：`pgrep -fl 'claude -p'`。

## 员工报「还有进行中的任务」

员工手上已有另一个进行中的任务时，新条目不会派给他，而是推迟，不算失败；等他做完、合并或放弃之后再派。

## 目标文本里的表格错位

目标和聊天消息按 Markdown 渲染。从终端里复制的框线表格（`┌─┐│`）在中文字体里本来就对不齐；用列表写字段说明，或使用标准 Markdown 表格（`| a | b |`）。
