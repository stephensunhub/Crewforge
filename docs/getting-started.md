# 快速开始

这篇带你从零跑通：安装 → 创建员工 → 新建项目 → 让团队开始干活。

## 1. 前置条件

| 需要 | 说明 |
|---|---|
| macOS | 目前只在 macOS 上使用和验证 |
| Rust | 支持 edition 2024（1.85 以上），用 [rustup](https://rustup.rs) 安装 |
| Node.js | 较新的 LTS 版本，用来构建前端 |
| Claude Code CLI | 员工的执行引擎，需要已安装并登录（`claude` 命令可用） |
| git | 每个任务一个 git worktree，项目必须是 git 仓库且至少有一个提交 |
| 可选：GitHub Copilot CLI | 想让员工用 Copilot 时安装 |
| 可选：Ollama 或其他 Anthropic 兼容服务 | 想用本地模型当员工时，见 [连接本地模型](endpoints.md) |

## 2. 安装

### 开发运行

```sh
npm install
npm run tauri dev
```

### 构建并安装到 /Applications

```sh
./scripts/install-mac.sh
```

脚本会构建应用、退出旧版本、复制到 `/Applications`、**重新做完整签名**再打开。重装请走这个脚本，不要手动复制：Tauri 打出的包只有临时签名，macOS 的「本地网络」授权（访问局域网里的 Ollama 需要）不会生效。

> 装之前请确认没有员工在干活，重启会打断他们。被打断的自主推进批次在预算够时会自动接着做。

数据存放在 `~/Library/Application Support/Crewforge`（可用环境变量 `CREWFORGE_HOME` 改位置），包括数据库 `crewforge.db`、事件流水 `events.jsonl` 和各员工的工作区 `worktrees/`。

## 3. 创建员工

打开左侧栏顶部的「公司」页：

1. 新建员工，起一个名字，写一段身份说明（职责、风格）。
2. 选择 **LLM 通道**：本机订阅（Claude Code / Copilot）或你配置的自建端点，再选通道里的模型。
3. 员工的**能力上限**（1–5 级）默认按模型自动给，可以手动改。

建议起步配置：一位负责人、一到两位开发、一位 QA。有架构师的话会先做设计。

## 4. 新建项目

1. 在「公司」页点「＋ 新建 / 导入项目」，选择一个本地目录（没有 git 仓库的目录先 `git init` 并提交一次）。已有代码的目录选中后会自动勾上「已有项目」：先做只读扫描和测试基线，确认后才让员工开发；全新项目不要勾。
2. 打开项目的「成员」页，点「＋ 添加成员」，把员工加入项目并指定角色：负责人、开发、QA、评审或架构师。
3. 已有代码的项目到「导入」页走完只读扫描、基线和确认。

## 5. 写目标，开始干活

1. 打开「计划」页，在「项目目标与硬性约束」里写清楚：要做什么、技术栈、不做什么、怎么验收。这段文字会带进每个员工的每个新任务，写得具体比写得长更重要。
2. 让负责人起草计划（或手动添加计划条目）。有架构师时，会先出现设计条目。
3. 在「职责」页设置每批次的调用数和时间预算，点「开始自主推进」。这一步会同时批准提议中的计划条目，也就是你对计划的最后确认。
4. 之后你主要在这几个地方观察：群聊（谁在做什么）、计划（进度和等待原因）、任务（改动和合并）、议题和行动项（需要决定的事）。

## 6. 第一次使用的检查清单

- [ ] `claude` 命令在终端里能正常对话。
- [ ] 项目是 git 仓库，主工作区干净（员工的合并会被未提交的改动拦住）。
- [ ] 用自建端点的话，在「模型 → 自建端点」点「测试连接」通过。
- [ ] 目标里写了验收标准。
- [ ] 预算设置合理，尤其是订阅员工（一定计入预算）。

遇到问题看 [常见问题与排错](troubleshooting.md)。
